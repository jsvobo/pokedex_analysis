================================================================================
DETECTING POWER CREEP: WHAT DO WE NEED TO KNOW BEFORE USING GLMs?
================================================================================

Our goal is to detect power creep — any statistically provable rising trend in Pokémon statistics across generations. Before applying Generalized Linear Models, we must understand our data to choose appropriate model specifications.


WHAT VARIABLES COULD SHOW POWER CREEP?
--------------------------------------------------------------------------------

Power creep could manifest in any combat-relevant statistic:

    Individual Stats:
        • Attack        - Physical damage output
        • Sp. Attack    - Special damage output
        • Defense       - Physical damage resistance
        • Sp. Defense   - Special damage resistance
        • HP            - Survivability
        • Speed         - Turn order advantage
    
    Composite Measures:
        • Total Stats   = HP + Attack + Defense + Sp.Attack + Sp.Defense + Speed
        • Offensive     = Attack + Sp.Attack
        • Defensive     = Defense + Sp.Defense
        • Physical      = Attack + Defense
        • Special       = Sp.Attack + Sp.Defense

To prove power creep, we need to show that at least ONE of these variables has a statistically significant positive relationship with generation.


================================================================================
WHAT DO WE NEED TO KNOW ABOUT THE DATA TO USE GLMs?
================================================================================

To use Generalized Linear Models correctly, we must determine:

    1. What TYPE of variable are we modeling?
    2. What DISTRIBUTION does it follow?
    3. How does VARIANCE relate to the MEAN?
    4. What LINK FUNCTION is appropriate?
    5. Are model ASSUMPTIONS satisfied?

Let's examine each requirement:


--------------------------------------------------------------------------------
1. TYPE OF VARIABLES
--------------------------------------------------------------------------------

A. THE PREDICTOR: GENERATION AS A CATEGORICAL VARIABLE

Generation is our key predictor, and how we encode it fundamentally affects our analysis. There are two possible approaches:

If we treat generation as a numeric variable (1, 2, 3, ..., 9), the model assumes a linear relationship with the response. This gives us a single coefficient representing the slope — "each generation adds β attack points." However, this approach cannot capture non-monotonic patterns. If Generation 2 has lower attack than Generation 1, a linear model would miss this entirely.

If we treat generation as a categorical factor, the model makes no assumption about the shape of the relationship. Instead of one slope, we get a separate coefficient for each generation compared to a reference level. This allows the model to capture any pattern: increases, decreases, dips, or spikes. The trade-off is that we use more degrees of freedom (8 coefficients instead of 1).

We choose to treat generation as a categorical factor for several reasons:

    • We do not want to assume power creep follows a linear trend
    • We want to detect any generational differences, not just linear ones
    • Our exploratory analysis already shows non-monotonic patterns — Generation 2 and Generation 6 both dip below Generation 1
    • Categorical encoding gives interpretable comparisons: "How does Gen 7 compare to Gen 1?"

In practice, Generation 1 serves as the reference level. The model estimates 8 coefficients (for Generations 2 through 9), each representing the difference from Generation 1. A significant positive coefficient for Generation 7 means that Gen 7 Pokémon have significantly higher Attack than Gen 1 Pokémon, after controlling for other factors.

For complementary trend analysis, we also fit models with generation as a numeric variable. This allows us to test whether there is a significant linear component to any generational change, which is useful for formal trend tests like the Jonckheere-Terpstra test.


B. THE RESPONSE: TYPE OF TARGET VARIABLE

The type of response variable determines which GLM family is appropriate. GLMs can handle continuous variables, count data, binary outcomes, and proportions — but each requires a different distributional assumption.

Our primary target, Attack, is a continuous variable that can take any value within its range (from 5 to 181 in our dataset). The same is true for all combat stats: HP, Defense, Special Attack, Special Defense, and Speed. Because these are continuous measurements rather than counts or categories, the Gaussian (normal) family is the natural choice. The Gamma family serves as an alternative when we want to ensure predictions remain strictly positive or when we suspect the variance increases with the mean.

Poisson regression would not be appropriate here because our stats are not count data — Attack of 75 is not "75 occurrences of something." Similarly, logistic regression is designed for binary outcomes like "Has Mega Evolution: yes/no," not for continuous measurements.

For secondary analyses involving count variables like Number of Abilities (which takes integer values 0, 1, 2, 3, or 4), we would use Poisson regression instead.


--------------------------------------------------------------------------------
2. DISTRIBUTION OF THE RESPONSE
--------------------------------------------------------------------------------

Beyond knowing the variable type, we need to examine the actual distribution of our response. For Gaussian GLMs to be appropriate, the data should be approximately normally distributed without severe skewness or heavy tails.

Looking at our combat stats, Attack has a mean of 77.5, median of 75, and standard deviation of 29.8. The skewness is +0.28, which is considered approximately symmetric — the distribution is well-behaved for Gaussian modeling. Speed shows similar behavior with skewness of +0.39, also approximately symmetric.

However, not all stats are equally well-behaved. HP shows the highest skewness at +1.51, which is considered highly skewed — there are several Pokémon with extremely high HP (up to 255) creating a long right tail. Defense (+0.96), Special Attack (+0.58), and Special Defense (+0.82) fall in the moderately skewed range. Interestingly, Total Stats has skewness of -0.09, making it the most symmetric variable, which makes sense as sums tend toward normality by the Central Limit Theorem.

The varying skewness across stats suggests that while Gaussian GLM is reasonable for Attack (our primary target) and Speed, we should be more cautious with HP and Defense. For these more skewed variables, Gamma GLM may provide a better fit.

--------------------------------------------------------------------------------
3. VARIANCE-MEAN RELATIONSHIP (HOMOSCEDASTICITY)
--------------------------------------------------------------------------------

A critical distinction between GLM families lies in how they model the relationship between variance and mean. Gaussian models assume constant variance — the spread of the data remains the same regardless of the predicted value. Poisson models assume variance equals the mean, which is appropriate for count data. Gamma models assume variance is proportional to the square of the mean, making them suitable when larger values show more variability.

For our analysis, we need to determine whether the variance of combat stats remains constant across generations, or whether it changes systematically. If variance increases with higher means, a Gamma model might be more appropriate than Gaussian.

CHECKING VARIANCE FOR SIMPLE MODELS (stat ~ generation)

Since generation is a categorical factor with 9 levels, a simple model like "attack ~ gen" produces only 9 unique fitted values — one for each generation. This creates a problem for standard residual diagnostic plots: instead of seeing a scatter of points, we see vertical lines at each of the 9 fitted values.

To properly assess homoscedasticity for simple models, we instead examine the distribution of residuals within each generation using boxplots. If variance is constant, the boxplots should show similar spread (interquartile range) across all generations. We also compute the standard deviation of residuals per generation directly.

Looking at Attack, the residual standard deviations by generation range from approximately 25.6 (Gen 6) to 32.9 (Gen 7). While there is some fluctuation, no generation shows dramatically more or less variability than others. The boxplots confirm this — the spread of residuals is relatively consistent across generations.

CHECKING VARIANCE FOR FULL MODELS (stat ~ generation + controls)

Simple models are not representative of our actual analysis, which will include multiple predictors. When we add continuous control variables (HP, Defense, Speed, etc.), the fitted values gain proper continuous spread, and standard diagnostic plots become meaningful.

For the full model with controls, we examine:

    1. Residuals vs Fitted plot — Should show random scatter around zero with consistent vertical spread. A "funnel" shape (wider spread at higher fitted values) indicates heteroscedasticity.

    2. Scale-Location plot — Shows √|standardized residuals| vs fitted values. A flat loess line indicates constant variance; an upward slope suggests variance increases with the mean.

    3. Q-Q plot — Checks whether residuals are normally distributed. Points following the diagonal line indicate normality.

FORMAL TESTING: BREUSCH-PAGAN TEST

We apply the Breusch-Pagan test for heteroscedasticity to both simple and full models. This test has a null hypothesis of constant variance (homoscedasticity). If p < 0.05, we reject constant variance.

For simple models (stat ~ gen), Attack shows p = 0.1723, indicating we cannot reject homoscedasticity. Most other stats also pass this test, though Special Defense is borderline (p = 0.0475).

More importantly, we test the full models that match our actual analysis. These results are more relevant since they reflect the model specification we will use. Visual inspection of diagnostic plots from full models, combined with formal Breusch-Pagan tests, confirms whether the constant variance assumption holds in practice.

4. LINK FUNCTION CHOICE
--------------------------------------------------------------------------------

In a GLM, the link function connects the linear predictor (the combination of our variables and coefficients) to the expected value of the response. The choice of link function determines how we interpret the relationship between predictors and outcome.

THE IDENTITY LINK

The identity link is the simplest choice: it assumes the expected response equals the linear predictor directly. Mathematically, E[Y] = β₀ + β₁X₁ + β₂X₂ + ... This means each unit increase in a predictor adds a fixed amount to the response.

For our analysis, this translates to statements like "Generation 7 Pokémon have 8.5 more Attack points than Generation 1 Pokémon, holding other factors constant." The coefficients have direct, intuitive interpretation in the original units of the response variable.

THE LOG LINK

The log link models the logarithm of the expected response as a linear function of predictors: log(E[Y]) = β₀ + β₁X₁ + ... This implies multiplicative rather than additive relationships. Each unit increase in a predictor multiplies the response by exp(β).

With a log link, coefficients represent percentage changes. A coefficient of 0.10 means approximately a 10% increase in the response per unit increase in the predictor. This is appropriate when we believe effects compound proportionally rather than add linearly.

The log link also guarantees positive predictions, which can be important for strictly positive variables. However, for our combat stats that range from 5 to over 200, the risk of predicting negative values with an identity link is negligible.

THE LOGIT LINK

The logit link, log(p/(1-p)) = Xβ, transforms probabilities to the entire real line. It is designed for binary outcomes or proportions bounded between 0 and 1. Since our combat stats are continuous measurements, not probabilities, the logit link is not appropriate for this analysis.

OUR CHOICE: IDENTITY LINK AS PRIMARY

For detecting power creep, we use the identity link as our primary specification for several reasons:

First, it provides the most interpretable coefficients. When we report that "Generation 7 has a coefficient of +8.5," readers immediately understand this means 8.5 more Attack points — no transformation required.

Second, there is no theoretical reason to expect multiplicative effects. Power creep, if it exists, likely manifests as game designers adding a few extra stat points to newer Pokémon — an additive effect. We have no reason to believe Generation 7 Pokémon have "10% more attack" rather than "8 more attack points."

Third, our response values are well above zero. Attack ranges from 5 to 181, with a mean around 77. The risk of predicting negative values is essentially zero, so the log link's guarantee of positive predictions provides no practical benefit.

LOG LINK AS ROBUSTNESS CHECK

Despite preferring the identity link, we also fit models with a log link as a robustness check. If our conclusions about power creep depend heavily on the choice of link function, this would suggest the findings are artifacts of modeling choices rather than genuine patterns in the data.

If both specifications yield similar conclusions — generation is significant, later generations show higher attack — we can be more confident that power creep is a real phenomenon rather than a statistical artifact.


--------------------------------------------------------------------------------
5. CHECKING MODEL ASSUMPTIONS
--------------------------------------------------------------------------------

Before trusting our GLM results, we must verify that the model assumptions are reasonably satisfied. Violations of key assumptions can lead to biased coefficients, incorrect standard errors, and misleading p-values.

NORMALITY OF RESIDUALS

For Gaussian GLMs, we assume the residuals (the differences between observed and predicted values) are approximately normally distributed. This assumption affects the validity of confidence intervals and hypothesis tests.

We check this using Q-Q plots, where residuals are plotted against theoretical quantiles from a normal distribution. If residuals are normally distributed, points should fall approximately along a straight diagonal line. Deviations in the tails indicate heavy-tailed or skewed residual distributions.

We also apply the Shapiro-Wilk test for normality. However, with our sample size of over 1,000 Pokémon, this test is extremely sensitive — it will detect even trivial deviations from perfect normality that have no practical impact. Therefore, we rely more heavily on visual assessment through Q-Q plots than on formal test p-values.

MULTICOLLINEARITY

When multiple predictors are highly correlated with each other, the model has difficulty separating their individual effects. This leads to inflated standard errors and unstable coefficient estimates.

We assess multicollinearity using Variance Inflation Factors (VIF). A VIF of 1 indicates no correlation with other predictors; values above 5 suggest moderate multicollinearity; values above 10 indicate severe problems. For our combat stats, moderate correlations exist (Attack correlates with Defense around 0.44), but we verify that VIFs remain below problematic thresholds.

INFLUENTIAL OBSERVATIONS

Individual observations with unusual predictor values or large residuals can disproportionately influence model results. We use Cook's Distance to identify potentially influential points — observations with Cook's D above 0.5 or 1.0 warrant closer examination.

As a robustness check, we compare our OLS results with robust regression using Huber M-estimation, which downweights influential observations. If the two approaches yield similar coefficients, we can be confident that outliers are not driving our conclusions.

We also repeat our analysis on the outlier-free dataset (with statistical outliers removed) to verify that power creep findings persist when extreme values are excluded.

INDEPENDENCE OF OBSERVATIONS

GLMs assume observations are independent of each other. In our case, each Pokémon is a distinct design decision by the game developers. While Pokémon within the same evolutionary line share design elements, each entry in our dataset represents a unique creature with independently assigned stats.

One potential concern is that Pokémon within the same generation might be more similar to each other than to Pokémon from other generations (clustering). However, our primary interest is in comparing generations, and treating generation as a fixed effect accounts for this structure.

SUMMARY: OUR MODEL SPECIFICATION
================================================================================

Based on the data examination above, we now summarize our modeling approach for detecting power creep.

ENCODING THE KEY PREDICTOR: GENERATION

We treat generation as a categorical factor variable with Generation 1 as the reference level. This produces 8 coefficients (for Generations 2 through 9), each representing the difference from Generation 1. This encoding makes no assumption about the shape of the generational relationship — it can detect dips, spikes, or any non-monotonic pattern.

For complementary trend analysis, we also fit models with generation as a numeric variable (1, 2, 3, ..., 9). This tests whether there is a significant linear trend component and is required for formal trend tests like the Jonckheere-Terpstra test.

PRIMARY MODEL: GAUSSIAN GLM WITH IDENTITY LINK

Our primary specification is a Gaussian GLM with identity link:

    attack ~ gen + hp + defense + sp_attack + sp_defense + speed + rarity

This choice is justified by our data examination: Attack is continuous and approximately normally distributed, variance is relatively constant across generations (homoscedasticity), and the identity link provides directly interpretable coefficients in the original units (Attack points).

The coefficients tell us exactly what we want to know: "How many more or fewer Attack points does Generation X have compared to Generation 1, after controlling for other factors?"

ROBUSTNESS CHECKS

To ensure our findings are not artifacts of modeling choices, we also fit:

A Gamma GLM with log link, which handles positive skewness and guarantees positive predictions. If both Gaussian and Gamma models yield similar conclusions about generation effects, we can be more confident in our findings.

Models on the outlier-free dataset, to verify that extreme values are not driving the power creep signal.

Models on Normal-rarity Pokémon only, excluding legendaries and mythicals. This tests whether power creep exists among "regular" Pokémon or is driven entirely by the inclusion of powerful rare Pokémon in later generations.


================================================================================
WHAT CONSTITUTES PROOF OF POWER CREEP?
================================================================================

Before examining the data, we establish clear criteria for what would constitute evidence of power creep. This prevents post-hoc rationalization and ensures our conclusions are principled.

CRITERION 1: STATISTICAL SIGNIFICANCE

Generation must be a statistically significant predictor of at least one combat stat after controlling for other factors. We test this using Likelihood Ratio tests comparing models with and without generation. If the p-value is below 0.05, generation adds significant explanatory power beyond what the control variables provide.

CRITERION 2: DIRECTION OF EFFECT

For power creep specifically (not just any generational difference), the effect must be positive — later generations should have higher stats than earlier ones. Finding that Generation 7 has significantly lower attack than Generation 1 would be evidence of generational difference but not power creep.

We also test for monotonic trend using the Jonckheere-Terpstra test, which specifically examines whether there is an ordered increase across generations.

CRITERION 3: ROBUSTNESS

The effect should persist across multiple specifications and datasets:

    • Significant in both Gaussian and Gamma GLMs
    • Significant after removing statistical outliers
    • Significant among Normal-rarity Pokémon (not just driven by legendaries)

If the effect disappears under any of these robustness checks, our confidence in the power creep conclusion would be diminished.

CRITERION 4: PRACTICAL SIGNIFICANCE

Statistical significance alone is not sufficient. With over 1,000 observations, even tiny effects can achieve statistical significance. We also require the effect to be practically meaningful.

We assess practical significance using effect sizes. Cohen's d values around 0.2 indicate small effects, 0.5 medium effects, and 0.8 large effects. If generation has a statistically significant but trivially small effect (Cohen's d < 0.2), we would conclude that while power creep technically exists, it is too small to matter in practice.

With these criteria established, we now proceed to fit our models and test for power creep.
